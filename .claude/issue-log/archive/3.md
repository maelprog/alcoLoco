# Journal — #3 Squelette de l'API axum : config, erreurs, healthcheck, OpenAPI

Démarrée le 2026-08-20. Dépendances #1 et #2 mergées, `main` à `d9c65da`.

## Portée telle que comprise au lancement

L'issue pose les fondations transverses **avant** tout endpoint métier : config, pool
Postgres, type d'erreur unifié, `GET /health`, spec OpenAPI en dev, tests d'intégration.
Elle porte aussi les **conventions d'API** du briefing (§ *Conventions d'API*), qui
doivent être posées ici une fois pour toutes : UUID v7 côté application, erreurs
RFC 7807 `application/problem+json`, pagination par curseur, `timestamptz` / ISO 8601 `Z`,
`snake_case` dans les payloads.

## Contrainte connue au lancement — tests d'intégration et CI

⚠ **Il n'y a pas de service Postgres dans la CI** (dette ouverte, cf. briefing *Escalade*).
L'issue demande des « tests d'intégration branchés sur une base de test ». Les deux
exigences ne se concilient que d'une façon acceptable ici : les tests d'intégration se
**conditionnent à `DATABASE_URL`** et se sautent proprement en son absence, de sorte que
`cargo test --workspace` reste vert en CI. **Ajouter un service Postgres au workflow
relève de l'escalade** et est hors périmètre de cette issue.

Conséquence directe : un vérificateur ne doit pas conclure de la CI verte que les tests
d'intégration ont tourné. Ils doivent être rejoués **avec** `DATABASE_URL` contre une base
réelle.
