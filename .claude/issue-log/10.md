## À confirmer, léguée par #2 (vérification 3 de la PR #41, 2026-08-20)

`crates/db/migrations/20260819090000_initial_schema.sql:422` pose un
**`UNIQUE (lower(name))` global à toutes les catégories** sur `library_item`. Deux items de
catégories différentes ne peuvent donc pas porter le même nom.

C'est peut-être voulu, mais ce n'est écrit nulle part. **#10 tranche** : soit elle confirme la
portée globale, soit elle la restreint à la catégorie — auquel cas il faut une **nouvelle**
migration, la migration initiale étant append-only depuis le merge de #2.

## Dette léguée par #3 (vérification 2 de la PR #45, 2026-08-20)

**Le scan SQL de `crates/api/tests/database.rs` fera des fausses alertes sur ta migration.**

Le test `the_pool_the_api_builds_reaches_the_migrated_schema` compare l'**ensemble** des tables
déclarées par le SQL des migrations embarquées (scan textuel de `CREATE TABLE` / `DROP TABLE` sur
`db::MIGRATOR`) à l'ensemble des tables présentes dans `public`. Le sens de défaillance est le bon —
**22 cas sondés par le vérificateur, aucun trou silencieux** : aucune combinaison ne laisse le test
vert avec un schéma faux. Le coût est en **fausses alertes**, et c'est #10 qui les rencontrera la
première. Neuf modes de divergence mesurés, dont trois très plausibles dans une migration correcte :

- un **commentaire** contenant `CREATE TABLE` (`-- … we would CREATE TABLE consumption_log`) crée un
  fantôme et rend la suite rouge ;
- `CREATE TABLE` suivi d'un **retour à la ligne**, de deux espaces ou d'une tabulation → table non vue ;
- `DROP TABLE a, b;` ne retire que `a` ; `CREATE TABLE "quoted"`, `CREATE UNLOGGED TABLE`,
  `SELECT … INTO`, `ALTER TABLE … RENAME TO` divergent aussi.

⚠ La migration initiale contient **déjà** `CREATE TEMP TABLE profile (id uuid)` dans deux commentaires
(`crates/db/migrations/20260819090000_initial_schema.sql:270` et `:320`). Ça passe aujourd'hui par deux
hasards cumulés : le scan exige le littéral `create table ` (avec l'espace), et `profile` est de toute
façon déjà déclaré donc dédupliqué. **Le prochain commentaire qui écrit `CREATE TABLE <autre_nom>`
rendra la suite rouge sans raison.**

Correctif suggéré, à faire dans #10 : dépouiller les commentaires `--` et `/* */` avant le scan, et
accepter `\s+` entre les mots-clés — sept des neuf cas tombent. Ne pas *affaiblir* le test pour le
faire taire : son sens de défaillance est ce qui a fermé le constat majeur de #3.
